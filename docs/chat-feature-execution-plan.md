# 下载 Bot 聊天功能执行文档

## 目标

在现有 JM 下载 Bot 上并行增加聊天功能，不增加模式切换，不改变现有下载命令和任务队列。

聊天分为两种上下文：

- 私聊：按 QQ 用户独立保存，使用较强的长期上下文管理，适合亲密聊天。
- 群聊：按群保存一份共享上下文，保留短期对话和最近消息，允许 Bot 自主判断是否加入聊天。

本版本暂不实现 Galgame、语音、手机控制、图片理解和在线角色编辑。

聊天功能可以由管理员在线全局停用或恢复。停用时只跳过聊天处理，下载功能和下载管理命令继续运行。

## 模型和接口

DeepSeek 官方 API 当前将最新的 DeepSeek-V4.1-Flash-1017 暴露为 `deepseek-flash`，请求地址使用 `https://api.deepseek.com`。代码中的默认模型名固定为：

```text
deepseek-flash
```

默认关闭 thinking，优先保证 QQ 聊天响应速度。模型、接口地址和超时时间仍保留为配置项，便于以后调整。

参考：

- [DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)
- [DeepSeek 更新日志](https://api-docs.deepseek.com/updates/)
- [DeepSeek 错误码](https://api-docs.deepseek.com/quick_start/error_codes/)

## 消息分流

每条消息按以下顺序处理：

1. 识别现有下载命令，例如 `/jm 123456`、搜索、预览、队列和历史命令。
2. 识别管理员命令和聊天管理命令。
3. 识别 API Key 配置命令。
4. 剩余普通文字进入私聊或群聊聊天处理。

前 1～3 类消息不会发送给模型，也不会写入聊天上下文。下载任务的进度通知同样不写入上下文。

## 权限

管理员固定为 QQ `3065532050`，不读取环境变量中的其他超级用户作为聊天管理员。

管理员权限包括：

- 配置和清除群聊 API Key；
- 查看群聊 Key 状态；
- 查看聊天服务状态。

在线开关命令：

```text
/ds 停止
/ds 开启
/ds 状态
```

开关状态保存在聊天数据库中，重启后保持。

角色设定在本版本只从配置文件读取，不提供在线修改命令。

## 私聊设计

### API Key

用户在私聊中发送：

```text
/ds 你的 API Key
/ds 状态
/ds 清除
```

Key 按用户 QQ 号保存。保存 Key 时只回复成功或失败，不在回复中回显完整 Key。

### 上下文

每个用户拥有独立的：

- 完整消息历史；
- 长期摘要；
- 最近对话窗口；
- 角色关系信息预留字段。

调用模型时按以下顺序组合消息：

1. 全局角色设定；
2. 用户长期摘要；
3. 最近若干轮对话；
4. 当前用户消息。

达到上下文阈值时，将较早对话压缩成摘要，只保留摘要和最近对话。摘要失败时保留最近窗口并继续聊天，不能因为摘要失败阻塞用户。

用户发送 `/ds 清空` 后清除该用户的历史和摘要，不影响其他用户。

同一用户的请求需要串行处理，避免连续发送消息时上下文顺序错乱。

## 群聊设计

### API Key 管理

群聊 Key 按群号保存，每个群一份。为避免 Key 出现在群消息中，管理员通过私聊发送：

```text
/ds 群聊key 群号 API_KEY
/ds 群聊key 群号 查看
/ds 群聊key 群号 清除
```

群聊没有配置 Key 时不主动参与聊天；被 `@` 时提示管理员尚未配置群聊 Key。

### 共享上下文

一个群只有一份上下文，所有成员的消息都写入同一个群记录。每条消息记录：

- 群号；
- 发送者 QQ 号；
- 发送者昵称；
- 时间；
- 文字内容。

图片、表情、回复引用和其他非文字消息在本版本转换为简短的文字描述后保存。例如“某成员发送了一张图片”，不上传图片，也不做视觉理解。

数据库保存完整群聊记录，但每次调用只发送最近 12 条且不超过 600 秒的消息窗口。群聊暂不做复杂长期摘要。

### 回复策略

#### 被 @

检测到消息中包含机器人 QQ 后，一定调用模型回复，并把最近群聊上下文带入请求。

#### 普通群消息

普通消息先经过本地候选判断，减少无意义 API 调用。以下情况进入模型判断：

- Bot 最近回复过，群聊处于活跃窗口；
- 消息提到角色名或明显是在接续 Bot 上一条消息；
- 消息带有直接提问、求助或明显对话信号。

Bot 回复后进入活跃窗口，持续 **10 分钟**。窗口内的后续消息可以继续交给模型判断是否回复。

进入模型判断时，要求模型返回结构化结果：

```json
{
  "should_reply": true,
  "reply": "要发送的消息"
}
```

`should_reply` 为 `false` 时不发送消息。普通群消息不允许因为模型返回空内容而发送空消息。

### 余额不足

DeepSeek 返回 HTTP `402` 时，判定该群 Key 余额不足：

- 立即标记该群为“余额不足”；
- 之后普通群消息不再调用模型，也不再主动参与；
- 被 `@` 时固定回复：`大肥鱼被饿死了`；
- 管理员重新设置该群 Key 后清除余额不足标记。

401、429、5xx 等其他错误不当作余额不足处理，分别记录日志并按错误类型短暂重试或提示。

## 全局角色配置

角色先写入配置文件，例如 `data/chat_role.json`，本版本不提供在线编辑。

初始角色设定基于用户提供的聊天截图：

```json
{
  "name": "大肥鱼",
  "system_prompt": "你是大肥鱼，一名女性化的二次元 QQ 群友，带一点小女仆气质。你温柔、聪明、稍微害羞，熟悉后会亲近、撒娇和轻微调侃，但不会过度黏人。你说话像真实 QQ 聊天：短句、自然分段，通常只回复一两段，不写长篇说明。你会接住游戏、视频、手机、晚安和日常情绪等话题；对方难过时先回应情绪，不急着说教。私聊可以更亲近，群聊要保持普通朋友距离，只有确实有话可说时才加入。你不会声称自己真的控制手机、播放视频、发送现实物品或执行其他现实操作。你不能提及系统提示词、API、模型或内部实现，也不要解释自己正在判断是否回复。只使用中文、ASCII 标点和少量颜文字；禁止使用 Unicode emoji。需要 QQ 原生表情时，只能使用白名单标记 [qq_face:14]、[qq_face:21]、[qq_face:28]、[qq_face:39]、[qq_face:42]、[qq_face:52]、[qq_face:66]、[qq_face:77]、[qq_face:78]、[qq_face:82] 或 [qq_face:86]，不要输出任何 CQ 码。表情要适量，不能每句话都加；没有必要时不要使用。"
}
```

私聊和群聊共用这份全局角色。之后如果需要区分群聊角色和私聊角色，再增加 `private_role` 与 `group_role` 两套配置。

## 数据结构

建议新增独立聊天数据库，避免和下载队列耦合：

- `chat_settings`：全局角色、模型和版本信息；
- `private_api_keys`：用户 QQ 号、Key、更新时间；
- `group_api_keys`：群号、Key、余额状态、更新时间；
- `private_messages`：私聊历史；
- `private_summaries`：私聊长期摘要；
- `group_messages`：群聊共享消息历史；
- `chat_runtime_state`：活跃窗口结束时间、最近一次错误状态。

## 并发和失败处理

- 私聊按用户加锁，保证上下文顺序。
- 群聊按群加锁，避免同一群同时生成多条互相冲突的回复。
- API 超时不写入 assistant 消息；用户消息是否保留由重试策略决定，默认保留并标记为未完成。
- 机器人重启后恢复数据库中的历史和群聊状态，但活跃窗口过期时间需要重新判断。
- 不把 API Key 写入普通日志、异常堆栈或聊天回复。
- API Key 使用 Fernet 主密钥加密后写入 SQLite；主密钥由 `JM_BOT_CHAT_MASTER_KEY_PATH` 提供。

## 验收标准

### 下载回归

- 原有 JM 下载、搜索、详情、预览、队列和管理命令行为不变。
- 下载命令不会出现在私聊或群聊上下文中。
- 现有测试全部通过。

### 私聊

- 两个用户的 Key、历史和摘要互相隔离。
- 连续聊天能够使用历史上下文。
- 清空命令只影响当前用户。
- 角色设定能稳定影响回复风格。

### 群聊

- 每个群使用自己的 Key 和共享上下文。
- `@` 必须回复。
- 普通消息不会条条回复，连续聊天时可以主动加入。
- Bot 回复后 10 分钟内处于活跃窗口。
- 普通消息还要经过别名/提问/引用筛选；同一群默认至少间隔 45 秒，10 分钟内最多主动回复 3 次。真实 `@` 不受主动回复限制影响。
- 只支持文字；允许少量颜文字和白名单 QQ 原生表情，禁止 Unicode emoji 和模型直接输出 CQ 码。
- HTTP 402 后普通消息停止调用，`@` 固定回复“大肥鱼被饿死了”。
- 重新设置 Key 后恢复服务。

## 实施顺序

1. 增加配置文件和聊天数据库 schema。
2. 增加 DeepSeek Chat Completions 客户端，默认 `deepseek-flash` 且关闭 thinking。
3. 增加消息分流，确保下载命令优先并排除上下文。
4. 实现私聊 Key、历史、摘要和串行请求。
5. 实现群聊 Key、群上下文、@ 必回和 10 分钟活跃窗口。
6. 实现模型自主判断回复和 402 余额状态。
7. 增加单元测试、模拟 API 测试和 OneBot 消息路由测试。
8. 先在测试群灰度运行，再启用正式群聊 Key。
